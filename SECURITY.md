# Security policy

SENTINEL is an early local development project and is not suitable for production monitoring. Do not expose its default HTTP listener beyond loopback, and do not submit sensitive telemetry.

Report suspected vulnerabilities privately to the repository owner through GitHub's security advisory feature. Include affected version, reproduction steps, and impact. Do not include live secrets or personal data in public issues.

Telemetry, endpoint, alert, incident, and audit read endpoints require an administrator or analyst bearer token. The administrator token is generated per start unless `SENTINEL_ADMIN_TOKEN` is configured; `SENTINEL_ANALYST_TOKEN` optionally configures a separate analyst credential. Analyst credentials cannot reset simulations. This is a small configured role split, not user accounts or session-based authentication. Health, rule catalog, and scenario catalog endpoints are public. HTTPS can be enabled with certificate and key environment variables and enforces TLS 1.3. Setting `SENTINEL_CLIENT_CA` additionally requires a client certificate chaining to that CA. The current backend does not bind certificates to enrolled endpoint IDs, support certificate rotation/revocation, or remove the need for a bearer token. The Windows agent is read-only but has not been run on Windows 11 here. There is no formal release signing, dependency scanning pipeline, rate limiting, or external security review. The simulator creates synthetic records and does not execute attack actions.
